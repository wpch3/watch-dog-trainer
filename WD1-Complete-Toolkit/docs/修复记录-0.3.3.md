# v0.3.3：捕获状态拆分、暂停后预览与排队操作

## 用户情况与尚不能下的结论

用户已经先点捕获，再赚取/消费，仍遇到“还没有新鲜、稳定的对象”。之前上传的0.3.2报告证明扫描成功、资源候选唯一命中，但**不含任何捕获缓冲/心跳/数值数据**，无法据此断言这次必然是暂停、入口不触发或对象不合格。

检查旧代码发现两项明确的工具问题：

1. 未安装、从未命中、缓冲不可读、指针不合格/不稳定、心跳超过2秒，都被压成同一句错误。
2. `Current()`也要求2秒新鲜度，面板详情又只在选中行变化时刷新。游戏切出暂停后，可能既看不到已捕获的值，也来不及在窗口操作。这不是要求用户“必须更快点”就能解决的设计。

## 本次修改

- 捕获状态细分：`NOT_INSTALLED`、`HOOK_NOT_HIT`、`HOOK_CHANGED`、`HOOK_UNREADABLE`、`BUFFER_UNREADABLE`、`BUFFER_CHANGING`、`HIT_WITH_NULL_POINTER`、`POINTER_RANGE_REJECTED`、`POINTER_ALIGNMENT_REJECTED`、`POINTER_NOT_STABLE`、`READY_LIVE`、`CACHED_PAUSED_OR_STALE`、`CACHED_EXPIRED`、字段不可读/越界等。
- 显示并导出：入口执行计数、连续稳定采样数、距新心跳时间、指针是否见到/是否合法、缓冲和已安装跳转是否可读/一致、对象代次、原始资源样本及缓存标记。
- 不导出原始对象指针、捕获缓冲地址、账号、存档或内存转储。资源样本（例如现金数值）明确属于用户选择的诊断内容。
- 详情自动刷新，不需要反复重新选中同一行；刷新不会重置用户输入的增减数值。
- 超过2秒可查看**之前在有效样本下保存的缓存数值**，不会为了刷新画面而读取旧对象内存，更不会立即据缓存写入。
- 当前对象缓存在120秒内可用于预置持续开关；状态显示“等待新心跳”，仍只有同一代次/同一对象重新产生新鲜心跳后才开始写。
- 一次性增减按钮改为**“排队一次增减”**：必须已有稳定有效样本，绑定当前对象/代次/范围/增减量，等待确认之后的新心跳再执行。30秒未刷新取消。没有命中过的入口不能排队，也不会猜一个新对象。
- 新增取消排队；STOP、模式切换、对象改变、授权过期、捕获代码变化都会取消。请求执行前从队列移除，任何异常都不自动重试增量。
- 无限/增加依然独立。当前无限/锁定与同字段增减互斥，增加不会启动无限。

**2秒的真正写入保护仍保留。** 本次不是把超时改成无限大，也不是放宽未知指针/签名/字段范围。

## 验证

新增39项捕获/暂停/排队回归，覆盖：

- 模拟切窗停更5秒后缓存仍可核对，但旧即时写入保持拒绝；
- 排队没有立即写入，同对象新心跳只执行一次；重复提交、迟到心跳、超时不重复加钱；
- 连续维持的预置不写旧对象；恢复心跳才开始；
- 指针/范围/授权/捕获代码变化取消；当前接口不触发与缓存过期分别显示；
- 无缓冲、无效对齐、空指针与不可读状态；
- 报告字段完整且不含原始指针；缓存预览不再读取陈旧指针内存。

原47项文件核心、51项原生模拟、48项映像扫描、335项Lua断言维持通过；微软net48框架成员引用728项、缺失0。两个窗口仍只在Linux Mono/Xvfb冒烟，**没有用户Windows修复后捕获效果验证**。

## 建议用户先做的最小诊断

1. 旧工具已经安装过捕获代码，先“恢复代码并断开”；不能恢复时先正常退出游戏，再关闭旧工具。
2. 覆盖工具目录的EXE/config，确认标题0.3.3；游戏/插件/功能计划无需重装。
3. 只读连接后选“增加金钱”，点捕获；先观察新的执行计数/状态，不点排队或任何无限开关。
4. 若已有有效数字，核对是否与游戏现金一致；若仍不行，直接导出新的 `WD1-Native-Probe.json`。这次含捕获数据。
5. **执行次数一直是0时，不再反复买东西。** 这表示需要继续核查入口实际使用，而不是把“签名唯一”当作“捕获成功”。

只有报告显示正确对象和值，并满足真实备份/单机条件后，再进行小额一次性操作验证。功能范围、Lua插件和原生指令契约本次未修改。
