# 0.4.1：反馈回路与指引修复（不改游戏逻辑）

## 用户实测反馈（2026-09-15）

1. 原生面板：无限电池、增加金钱 **均生效**（此前加钱已验证，电池为新验证项）。
2. 点 [PING] 弹出 "UI4 PING received"，但面板 Clicks 不涨。
3. 无限弹药 / 无限专注 未生效。
4. 技能点添加提示 `WD1KIT: NOT_ARMED`。
5. 07 页罪恶值/任务XP操作流程看不懂。

## 判定与修复

1. **PING 弹出通知 = 按钮动作确实执行了**（那条通知就是动作本身发的）。Clicks 不涨说明宿主的 Layout 只在构建时绘制一次、Rerender 不重跑布局，面板文字无法实时刷新。修复：**计数器改走通知通道**——PING 现在直接回弹 `clicks/polls/armed` 数值，`[STATUS]` 通知也带上全套计数。面板数字从此只当"静态参考"。
2. **弹药未生效**：弹药是"会写进存档"的持续功能，按设计需要 **2 小时有效备份回执**；回执缺失/过期时被 `BACKUP_TICKET_INVALID` 拒绝。这不是 bug，是备份安全门槛。修复：所有拒绝通知现在附带**下一步指引**（如 `NOT_ARMED - tick the [ARM] checkbox first`、`BACKUP_TICKET_INVALID - reinstall plugin with a fresh backup (2h)`）。
3. **专注未生效**：最可能是同一时段核心已被暂停/未 ARM（任何暂停都会自动停全部效果并要求重新 ARM，此为既有安全契约）。新提示码会把具体原因弹出来，照提示重试；若仍无效，`[STATUS]` 通知行发回即可诊断。
4. **07 页看不懂**：新增 `docs/使用指引-逐步操作.md`（手把手版），页面顶部也加了四步英文提示（ARM → 点一个奖励 → CONFIRM → 看通知）。
5. **原生面板捕获能否简化**：不动 exe（用户已有两条验证通过的路线，不冒重建风险）。在指引中写明"一次捕获管一片、管一次开机"的实际频率：连接扫描 1 次/开机，钱包/电池/车辆各 1 次/开机，2 小时内增减无需重复捕获；并解释为何不能完全去掉（对象识别安全底线）。

## 验证

- 五套 Lua 测试 + 验证器全绿；新增 5 条断言：NOT_ARMED 拒绝必须带 [ARM] 指引、缺回执拒绝必须带 backup 补救指引、STATUS 通知必须带计数。
- 目录、桌面 EXE、原生引擎均未改动。
