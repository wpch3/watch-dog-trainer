# v0.3.3 开发与构建

## 当前结构

- `src/Companion`：中文管理窗口、游戏安装定位、备份/安装/恢复入口。
- `src/Native/Contracts.cs`：有来源的候选指令/字段事实、独立功能契约、限定捕获码生成。
- `src/Native/Memory.cs`：Windows x64 进程读取/分配/短暂安全写入窗口/代码恢复；无驱动、无提权、无进程终止。
- `src/Native/Engine.cs`：原字节校验、捕获心跳、对象绑定、单项维持/单项增量、互斥、断开恢复。
- `src/Native/NativeForm.cs`：筛选、收藏、每项开关/状态、单次操作、快捷键、脱敏候选报告。
- `src/Plugin`：原有 Lua 状态机及三类完整白名单批次。
- `src/Shared`：备份、哈希、路径、事务与样式。
- `plan` / `data/complete_plan.*`：完整用户计划和原玩法验收，当前绑定状态单独记录。

没有旧平台成就源目录、桥接 DLL 或 API 数据。Steam 的存在仅用于游戏版本/安装/用户主动启动。

## 编译

终端在项目根目录；最终用户不需要编译器。

**必须使用微软官方 net48 参考程序集，不能只用 Mono 默认API。** 参考包为 `Microsoft.NETFramework.ReferenceAssemblies.net48` 1.0.3；解包后将 `WD1_NET48_REFS` 指向 `build/.NETFramework/v4.8`，其中应有 `mscorlib.dll` 和 `RedistList/FrameworkList.xml`。引用包只用于编译，不随运行程序分发。

Linux（本轮使用）：

```bash
# Mono 开发环境、Python3、Lua5.1；Xvfb仅用于GUI冒烟
python tools/build_release.py /usr/bin/mcs --framework-refs "$WD1_NET48_REFS"
lua5.1 tests/test_plugin.lua
```

Windows：安装有 .NET Framework 4.8 参考程序集的 C# 编译工具后，将 Roslyn `csc.exe` 路径传给同一个 Python 脚本，并使用 `--framework-refs` 指定微软v4.8参考目录。源码语法基线 C#7.2。Windows 11 运行时无需安装 Mono。

编译测试：

```bash
mcs -noconfig -nostdlib+ -target:exe -langversion:7.2 -platform:x64 \
  -define:WD1KIT_FIXTURES -main:WD1Kit.Tests.Runner \
  -out:release-tests/Test-Core.exe \
  -r:"$WD1_NET48_REFS/mscorlib.dll" -r:"$WD1_NET48_REFS/System.dll" \
  -r:"$WD1_NET48_REFS/System.Core.dll" -r:"$WD1_NET48_REFS/System.Drawing.dll" \
  -r:"$WD1_NET48_REFS/System.Windows.Forms.dll" -r:"$WD1_NET48_REFS/System.Web.Extensions.dll" \
  src/Shared/*.cs src/Native/*.cs src/Companion/Program.cs \
  tests/Test-Core.cs tests/Test-Native.cs tests/Test-ImageScan.cs tests/Test-Capture.cs
mono release-tests/Test-Core.exe "$PWD"
```

测试符号只跳过临时假游戏的真实哈希匹配；测试仍检查发行 EXE 的 IL 含 `Identity.Require`。**发行编译不得使用该符号。** FakeMemory不会打开真实进程，不运行系统内存API。文件测试只写随机临时目录。

GUI冒烟（无游戏连接）：

```bash
xvfb-run -a mono WD1-Toolkit.exe --ui-smoke
xvfb-run -a mono WD1-Toolkit.exe --native-ui-smoke
```

## 下一步适配纪律

1. 不因一个相似名称存在就发明参数；新原生字段需可执行节签名、原字节与对象/类型证据。
2. 不将共享普通点数当所有数字之旅点数，不将同一个钱包复用四遍。
3. 不把共享计时器或全局暂停映射成全部小游戏。
4. 代码改写和数据锁定分开测试。数据范围只是防线，不是所属对象的证明。
5. 库存扣减、增加、当前持有、永久解锁、游戏内任务完成分开验收。
6. 回滚失败不允许报“已安全关闭”；不得结束游戏进程或关闭防护来掩盖失败。
7. 完整计划的 UNBOUND 项必须继续保留，只有证据与测试补齐才升级状态。

## 必需的发布API审计

用 Mono.Cecil（仅开发测试依赖）编译 `tests/Audit-Net48.cs`，再运行：

```bash
mono /path/to/Audit-Net48.exe WD1-Toolkit.exe "$WD1_NET48_REFS"
```

## 0.3.2扫描结构

`ImageScan.cs`把磁盘PE32+布局、实际映像页面和扫描预算分开；接口`IMemory.Code()`改为单次流式枚举。Engine先遍历数据块，再检查所有签名，并按实际命中地址去重。不要改回对每个签名重新读取整个映像。

`IScanState.ScanComplete`为false时禁止一切捕获与写入；`WinMemory.RequireScannedCode`同时检查已读取范围和当前页面属性。只读扫描的失败诊断与Engine生命周期分开，所以连接失败仍可导出，不得重新增加Need()/必须连接才能导出门槛。

## 0.3.3 捕获状态与暂停交互

`CaptureState.cs`是Engine的partial：原始跳转不改，增加状态、缓存、对象代次及一次性队列。UI读取`Preview`/`CaptureSummary`，不能再把`Current`的写入级新鲜度检查用来抹掉缓存预览。`Once`仍严格即时写入接口，UI用`QueueOnce`，必须等待排队后新心跳；不允许从从未命中/不合法对象建立队列。缓存只在有效新鲜采样中生成；暂停后预览不得访问旧指针。

不要在详情自动刷新时重置用户的数字输入；输入默认值仅在选择项变化时设置。STale有多个原因，界面不得假定就是游戏暂停。
