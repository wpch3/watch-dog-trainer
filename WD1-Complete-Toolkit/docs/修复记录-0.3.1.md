# v0.3.1：修复独立参数面板的 String.Split 缺失方法

## 用户报告

点击“03 游戏内参数 → 打开独立参数控制面板”时报错：

`找不到方法: System.String[] System.String.Split(Char, System.StringSplitOptions)`

路径已正确选择，其他前置操作正常。

## 已确认原因

这是工具的框架兼容性构建错误，不是游戏切出暂停、游戏路径、DLC 或存档造成。

v0.3 使用 Mono 的默认运行时参考程序集编译。源码的 `.Split(' ')` / `.Split(',')` 被绑定到 `String.Split(char, StringSplitOptions)`；该方法存在于当时的 Mono API 表面，但不在 Microsoft .NET Framework 4.8 的参考契约中。声明目标为4.8的配置文件并不能自动阻止编译器选择这个方法。

对**旧 EXE 实际元数据**使用微软 net48 参考程序集做解析，607个框架成员引用中恰有1个无法解析，即用户报错的此方法。界面方法在JIT解析调用时即可能失败，所以不需要进入游戏连接/捕获环节就能出现错误。

## 修复

1. 产品源码4处单字符分割调用改为显式 `char[]` + `StringSplitOptions.None`；测试夹具同样修正。
2. 构建必须显式使用 Microsoft .NET Framework 4.8 参考程序集，并加 `-noconfig -nostdlib+`，禁止静默使用 Mono 默认框架。
3. 添加 `.NETFramework,Version=v4.8` 目标属性；显示/文件版本改为0.3.1。
4. 增加 `tests/Audit-Net48.cs`，检查**最终生成 EXE**的外部框架成员引用，而不只在Mono上启动界面。
5. 原生签名、游戏修改逻辑、Lua插件、完整计划、白名单和原存档/配置位置不变。

构建参考包：Microsoft.NETFramework.ReferenceAssemblies.net48 1.0.3（官方NuGet发行）。
包SHA-256：`8a7e348538e7eb91351696911689f49e3d4f63f8bab517432bbe159b8b1104a2`。
参考程序集仅用于开发编译，**没有装进运行包，不要替换 Windows 的系统 DLL**。

## 本次验证

- 旧二进制：`NET48_MEMBERREFS_CHECKED=607`，`NET48_MISSING=1`，缺失项正是报告的 Split 方法。
- 新二进制：607个框架成员引用全部解析，`NET48_MISSING=0`；目标属性是 `.NETFramework,Version=v4.8`。
- 47项文件核心、51项原生模拟进程、335个Lua断言再次通过。
- 主窗口与独立参数面板在Linux Mono/Xvfb启动并关闭。
- 17个插件/计划数据文件与原v0.3发布包逐字节比对一致。

**没有用户机器上的修复后Windows实测，也没有因此认证任何游戏内效果。** 这次证实并消除了报告中的框架缺失引用，不代表所有原生候选已经通过游戏验证。

日志：`release-tests/net48-before-hotfix.log`、`net48-member-audit.log`、`hotfix-0.3.1.json`、`build-info.json`。

## 用户更新方式

1. 关闭旧工具。
2. 将热修复包的 `WD1-Toolkit.exe` 和 `WD1-Toolkit.exe.config` 覆盖到原工具文件夹。
3. 不用重装游戏、修改暂停设置、重新安装Lua插件或重新选择已保存的路径。原有备份不删除。
4. 打开后确认显示0.3.1，再进入“03 游戏内参数 → 打开独立参数控制面板”。
5. 先做“只读连接 / 扫描”，不要直接启用修改。

切出游戏自动暂停可能影响**之后的对象捕获心跳/数值刷新**，使界面暂时等待新数据；它不会造成 .NET 方法不存在。届时切回游戏触发对应菜单/活动即可，不要把这次构建错误归因到暂停。
