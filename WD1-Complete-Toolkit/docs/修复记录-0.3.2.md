# v0.3.2：可执行节范围处理与失败诊断

## 用户实机反馈

v0.3.1 的参数窗口能够打开，但“只读连接 / 扫描”返回“连接失败:可执行节范围异常”。用户确认三项哈希通过、目录正确、已在单机存档自由行走且不在车上。

该错误发生在PE节扫描阶段，不依赖角色位置、是否驾车或功能开关。无需重复换站位、重选路径或重装游戏。

## 旧逻辑缺陷

旧扫描器用同一句话报告两种不同条件：

1. 节的 `RVA + VirtualSize` 超过 `ProcessModule.ModuleMemorySize`；
2. 累计可执行节超过固定64MiB上限。

它没有解析/记录文件的 `SizeOfImage`，没有核对实际映像页面，没有分块扫描，也没有在连接失败后保留导出入口。因而**仅凭用户这一句错误，不能判断具体触发分支和实际数值**。不把猜测当成已在用户机器证实的根因。

## 本次修改

- 对通过原有三项指纹检查的磁盘引擎文件读取有限的PE32+头/节表；运行时头另作诊断比较，记录差异。
- 分开记录系统报告模块大小、磁盘/运行时 `SizeOfImage`、各节RVA/虚拟大小/原始大小/属性。
- 不再拿单个报告大小作所有扫描与补丁的唯一边界，也不直接取消边界。扫描区间必须在已校验磁盘映像合法节内，并逐段通过 `VirtualQueryEx` 检查同一映像分配、提交状态、页面属性。
- 标准读取块为2MiB，不一次分配整个节；地址跨度上限1GiB，实际可读代码预算512MiB，区域/时间预算仍保留。超过限制将明确记录具体错误码。
- 扫描当前同映像中可读、可执行的页面；已丢弃且明确标记可丢弃的节和当前非执行映射单独记录。外部分配、不可读代码、未知缺页、读取失败等会使扫描不完整。
- 节重叠规范化，块边界保留64字节尾部；候选按地址去重，避免块重叠产生假多匹配。
- **扫描不完整时，全部捕获/修改禁止执行**。补丁也只能写到完整扫描后实际确认过的代码范围，并在写前再次核对页面归属/属性与原字节。
- 连接失败仍保留 `ScanDiagnostic`，释放未完成连接的进程句柄，按钮改为**“导出诊断（失败也可）”**。

没有扩大成全进程扫描，没有读出或上传原始内存、存档、账号或路径。报告只有数值元数据、相对位置、页面决策、错误码和候选状态。

## 已做的验证

新增48项合成PE/映射页面/流式扫描检查，包括：

- PE32+格式、`SizeOfImage` 与节RVA独立解析，非法头保持拒绝并保留原始尺寸；
- VirtualSize为0、重叠节、超界/溢出节；
- 合法70MiB节不再触发旧64MiB上限，实际按35个2MiB块读取；
- 系统报告尺寸小于已验证映像时，仍只接受正确同分配映射范围；
- 无法读取、guard、外部分配、非映像页、被丢弃节、读入不完整；
- 预算、跨块特征、地址去重、一次枚举、不完整扫描禁止任何写入；
- **Engine没有成功创建时，也能构造并序列化失败诊断**。

原47项文件核心、51项原生模拟、335项Lua断言维持通过。新EXE继续用微软net48参考程序集构建，框架成员引用检查通过（682项，缺失0）。主窗口/参数窗口仍只有Linux Mono/Xvfb冒烟，**未在用户Windows重新运行验证**。

## 用户下一步

只替换工具目录的 `WD1-Toolkit.exe` / `.config`，不改游戏目录、存档、Lua插件或任何功能计划。再次点一次“只读连接 / 扫描”，**无论成功还是失败，都点“导出诊断（失败也可）”**，发送 `WD1-Native-Probe.json`。

这份报告能确认用户这次的真实模块大小、节表与页面状态，避免第三次依靠一句错误猜原因。在这些数据确认前，不把本次调整称为用户游戏适配完成。
